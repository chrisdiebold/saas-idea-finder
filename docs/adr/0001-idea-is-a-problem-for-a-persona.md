# An Idea is a problem for a Persona, not a product concept

The central unit of the system, the Idea, is a recurring problem experienced by one Persona (e.g. "landscapers
can't turn site photos into quotes"), not a product concept. Possible products are proposed only in an Idea's
Briefing. We chose this because evidence on the web describes problems, not products. If Ideas were products,
several of them would share the same evidence and count it twice, and you would be reviewing solutions before
knowing whether the problem is real.

Ideas are split by Persona when the people with the problem differ by industry or role, and connected with a
Related link instead of merged. Each vertical then gets its own evidence, Communities, pricing and distribution,
which suits a solo founder, while the Related link still shows the broader pattern.

## Consequences

- Clustering groups Signals by *problem and Persona*, not by topic. Two Signals about the same pain from
  different industries belong to different Ideas.
- Evidence that describes a product rather than a problem (launches, businesses for sale) can't be matched to
  an Idea directly. It attaches to a Competitor, which links to Ideas.
- Changing this later means re-clustering every Signal and invalidating every Review, Briefing and Working List
  entry, so it is expensive to reverse.
